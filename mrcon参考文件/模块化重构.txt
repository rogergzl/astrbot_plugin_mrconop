基于现有项目完成原子化、高内聚低耦合的模块化重构，严格遵守以下架构、目录、代码约束：
一、目录结构规划
插件根目录
仅放置 AstrBot 框架运行所需的必备文件、插件配置文件，以及两个顶层调度入口：main.py 和 web_panel.py。根目录不编写任何业务逻辑代码。
main.py：框架识别的插件主入口，负责初始化、调度core目录下全部核心业务模块；
web_panel.py：Web 服务总调度入口，常驻根目录，由main.py控制启停，仅负责调用、管理web目录内的所有 Web 功能模块。
core 子目录
集中存放插件全部核心业务逻辑。按照业务粒度做原子拆分，一项业务功能对应一个独立 Python 文件，细分模块包含数据库读写、Rcon 网络通信、服务端日志监听、用户权限校验、命令解析处理等，各模块各司其职。
web 子目录
集中存放所有 Web 面板相关内容，包含接口路由、前端模板、静态资源等，并继续在目录内按功能细分文件与子文件夹，所有 Web 能力统一由根目录web_panel.py进行调度管理。
二、代码强制规范
模块之间的引用全部采用Python 相对导入方式，严禁书写硬编码绝对路径，保障多环境部署兼容性；
严格执行单一职责设计，每个代码文件只实现一类功能，模块之间低耦合、相互独立；
整体架构分层明确，区分框架入口、业务核心、Web 服务三大板块，提升后期维护、功能扩展、问题排查效率。
